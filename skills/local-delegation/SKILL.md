# Local Model Delegation

Codex owns scope, commands, verification and integration. Local models receive supplied context and return proposals. Preserve the active host's native authentication, provider and permission rules. Explicit user restrictions override this workflow.

Use `python3.11 <plugin>/delegate.py`. Defaults use the shared private state home across projects. Read [contracts](references/contracts.md) when forming a brief. Missing or disabled routing means continue natively without setup, assessment or approval. Installation, assessment consent, model approval and route activation are separate decisions.

Follow the [coordinator policy and native-subagent integration](references/contracts.md#coordinator-policy-and-native-subagents), including its pointer to Vibe Setup when active. Read that project's installed policy rather than maintaining a copy here; native fallback must satisfy both contracts.

Choose `task_requirements.max_output_tokens` using the selected model's reasoning observations, task complexity and expected output size. Follow [generation budgets](references/contracts.md#generation-budgets): stay within the approved model ceiling and loaded context, keep thinking settings unchanged, and use native fallback when the required allowance is unsupported. An exhausted request with verified terminal evidence releases its slot; missing evidence remains uncertain. Never replay a completed or ambiguous task merely to try a larger allowance.

1. Choose a bounded task with predeclared acceptance checks. Follow the [coordinator policy contract](references/contracts.md#coordinator-policy-and-native-subagents), including active project instructions and relevant skills. Read approved operating scope and separate observed evidence; never infer ability from model name, size or a toy fixture ceiling. Use native verification for provisional larger contexts. Unknown savings permit ordinary approved work, not extra trials or unsupported savings claims. Resolve an exact native fallback from explicit task policy or trusted active-host metadata. If unavailable, keep work with the current native coordinator. Reuse `origin_chat_id` and `task_key` through compaction; `lookup` before resubmitting.
2. Submit once. When collection is initialized, bind project context with `--measurement-context`; follow [measurements](references/measurements.md). Missing measurement support does not authorize changing routing. For `waiting`, `reserved` or `running`, use `wait --job ID --seconds 5` (up to 60). Healthy occupied slots justify waiting. At `route_decision_required`, decide automatically whether expected benefit warrants a bounded extension or native fallback. Use `route decide --job ID --decision FILE` with the same job. Never ask the owner to switch models because local capacity is busy.
3. For `candidate_ready`, use `check --job ID` for bounded Python. For other capabilities, use `verify prepare`, `verify checks` and `verify record`. Review every acceptance criterion and summary claim. Execute only declared checks in the qualified sandbox; missing toolchains/isolation keep the task native. A candidate's claimed receipt or stdout is not verification. Keep the session token outside candidate-accessible files and prompts.
4. Apply only an `accepted` proposal with native editing tools, after comparing source hashes again. Run the destination project's required checks. The helper never applies project files. `needs_reassessment` means the snapshot changed; rebuild scope before attempting a distinct task.
5. For `fallback_required`, first verify the exact native model/effort and native delegation support are available and permitted by the active policy. If unavailable, keep execution with the coordinator and report that state; do not claim a task started. Otherwise use `fallback claim --task-name SHORT_TASK_NAME`, such as `habblaud_verification`, inspect native tasks for the returned name, and dispatch only if `may_dispatch` is true and no match exists. Follow the [native naming contract](references/contracts.md#coordinator-policy-and-native-subagents); retain the returned name through recovery. This skill authorizes native fallback delegation within the user's task, subject to any explicit prohibition. Apply the active native declaration and report contract before dispatch, including Vibe's harness-root declaration when required. Use the supported native tool, exact model/effort and a fresh context. Give source, contract and proposed-output location; forbid recursive local delegation. Keep independent oracle source private.
6. Immediately `fallback attach` the returned native task ID. An ambiguous dispatch requires `fallback reconcile` against the actual native task list; never blindly repeat it. Use native waiting tools, record the candidate with `fallback result`, then use the same verification contract. Failed native verification is terminal, not another fallback.
7. Follow [measurements](references/measurements.md) to record destination delivery, attributable native usage, and later corrections. Acceptance is not integration; successful fallback is not local success. Include briefing, verification, rewriting, fallback, and measurement overhead. Missing usage stays unknown. Read reports for recommendations only. Extra comparisons require separate bounded consent. Legacy `outcome record` retains global profile side effects; do not call it automatically as a second measurement sink. Synthetic trials do not establish project reliability or net account savings.

Display the actual model name while it generates and “Awaiting verification” after a candidate returns. Distinguish waiting, pending dispatch, confirmed native execution and unavailable fallback. Do not impersonate native agents or promise control over native app banners. [Read-only visibility](references/visibility.md) exports JSON by default, independently of routing; it never controls work. For explicitly requested Habblaud appearance, read that reference before enabling the separate opt-in hook adapter or attaching assignment context. Do not add role/specialty keys to a strict local brief or treat Habblaud completion as acceptance.

Use `Task description (via Model Display Name)` as the local progress title, for example `Habblaud verification (via Qwen3.8 27B Splash)`. Take the actual model display name from the saved attempt profile using the visibility guide's formatting rule. In progress details, keep task and model as separate labeled values. These are chat progress messages: local HTTP calls do not create Codex's native Subagents panel, and the plugin cannot set that panel's model column. A native fallback uses a readable task name and its actual native model; never carry the earlier local model label onto native execution. Habblaud's separate badge remains `Role · Model Display Name`.

Approved profiles with separate loading permission can load through the durable HTTP path before inference; see [loading and recovery](../../docs/model-loading.md). Loading refuses observed peers and preserves runtime settings. Ambiguous operations retain their reservation; use read-only reconciliation, never a blind retry. Reset requires explicit owner authorization and verified absence with admission off. Background recovery remains `lifecycle_unqualified`. Never fabricate ownership or use a model CLI, proxy or cloud API workaround. Model replacement requires fresh owner approval.
